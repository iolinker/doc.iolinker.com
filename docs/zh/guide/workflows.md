# 创建、版本与排障

## 从明确的流程开始

1. 在工作流模式选择**新建**，添加手动触发器。
2. 从节点菜单选择逻辑、工具或 AI 节点，连线形成执行路径。
3. 为每个节点配置输入和输出，保存后手动执行。
4. 检查执行记录，再添加定时或 API 触发。

[手动触发器](../trigger_start)适合调试；同步／异步 API 有各自的调用和返回语义，不能随意替换。

## 让 Agent 协助创建或修改

1. 在对话中给出明确目标、输入、处理步骤和期望输出。
2. 如页面显示“添加流程”，先创建入口，再要求 Agent 生成流程。
3. 检查工作流预览卡片和生成结果；需要进入画布时使用**打开流程**。
4. 要求修改时，查看**修改前后差异**，不要只凭“已修改”的文字保存。
5. 保存后检查版本和手动执行结果。

工作流工具用于 Agent 调用已启用的 API 流程，与 Agent 协助创建／编辑流程不是同一个功能。

## 调试与版本

- 在 Agent 对话或画布中执行调试，核对失败节点、输入和错误。
- 在流程版本入口查看变化、比较版本；回滚前确认要恢复的目标版本和当前未保存变化。
- 回滚版本不是删除执行记录，也不能撤销已经对外部系统产生的副作用。

## 执行记录与 AI 诊断

1. 打开目标流程的执行记录，选择失败执行。
2. 检查节点状态、错误、重试与关联链路。
3. 失败执行提供 AI 诊断入口时，可使用该入口辅助分析；诊断不是自动修复。
4. 回到画布修正，另做一次手动验证。

日志和诊断上下文可能包含凭证、提示词、业务数据或外部地址，分享前应脱敏。模型不可用时，诊断入口不代表能够完成诊断。

## 安全执行

外部请求、SSH、文件和脚本节点会触及实际系统。限制目标地址、目录和凭证，使用参数绑定，避免把用户输入拼接到命令或 SQL。先以无副作用数据调试，再启用无人值守触发。
