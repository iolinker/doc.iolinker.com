# 完成第一个任务

这条路径不依赖旧机器人触发器。先完成一个能在页面中检查结果的小任务，再考虑定时、远程访问或业务系统集成。

## 1. 启动并完成安全初始化

1. 从[官网下载区](https://iolinker.com/#cta)选择与操作系统、CPU 架构匹配的安装包；不要仅凭“NAS”名称选择架构。
2. 按启动程序的实际输出打开本地 Web 地址。端口以启动日志为准。
3. 完成首次登录，并立即通过账户菜单修改初始密码。文档不提供或建议固定默认凭证。
4. 未完成账户安全配置前，不要向公网开放服务，也不要分享 Cookie、令牌或配置文件。

详细边界见[安装与部署](deployment)。

## 2. 连接一个模型

1. 在 Agent 工作台打开对话；没有可用模型时，页面会显示模型配置提示。
2. 通过提示中的**快速配置**或**模型设置**入口，选择服务商并填写其要求的模型名称、接口地址和 API Key。
3. 保存并回到对话，确认模型状态已可用，再创建或选择 Agent。
4. 保留必要的工具选择，先不授权文件、命令或远程通道。

模型服务通常由第三方提供。发送给模型的提示词、会话、检索片段和工具数据可能传输到服务商；请先确认数据是否适合发送。保存配置不等于已建立网络连通或余额可用。

## 3. 完成第一次对话

1. 创建 Agent 后进入其对话页面。
2. 输入一个明确的小任务，例如：`总结这个 Agent 可以调用的能力，并告诉我哪些操作需要额外授权。`
3. 等待流式回答，检查返回的工具卡片、异常信息和任务结果。
4. 打开会话列表，确认该会话已保存；在对应入口查看链路，区分 Agent 会话与定时任务。

**完成标准：** 页面出现可阅读的回答，且没有模型鉴权或工具权限错误。不要仅凭“请求已发送”判断任务完成。

## 4. 创建第一个工作流

1. 切换到工作流模式，使用**新建**按钮创建空白流程。
2. 保留**手动触发器**，添加一个 [LLM 节点](../llm)，按界面要求选择模型凭据和输入。
3. 将结果连接到[流程输出](../output)，保存流程并手动执行。
4. 打开执行记录，检查各节点状态、输入输出和失败原因。

**完成标准：** 流程有明确的完成状态，输出与任务相符。第一次运行失败时先修正模型与节点配置，不要直接增加无人值守执行。

## 5. 再逐步扩展

- 希望 Agent 协助生成或修改流程：阅读[工作流与排障](workflows)。
- 希望定时执行：阅读 [Agent 定时任务](schedules)，区分它与工作流 Crontab。
- 希望接入内部资料：先阅读[知识库与检索](knowledge)，确认模型配置。
- 希望使用表单和人工确认：阅读[表单与协作](forms)。

## 常见问题

- **没有模型可选：** 检查模型配置、当前项目与服务商设置；当前指南不假设所有部署预置模型。
- **任务一直等待：** 检查工具授权、模型响应和任务状态；不要把长耗时误认为成功执行。
- **找不到旧机器人菜单：** 旧触发器的新建入口已从当前节点菜单中隐藏。
- **安装包与文档不同：** 文档按当前源码界面核对，以安装包实际界面为准，不宣称所有旧版本具备这些能力。
