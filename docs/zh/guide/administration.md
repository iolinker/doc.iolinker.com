# 项目、角色与凭证

## 项目空间

项目用于组织 Agent、工作流、资源与成员。执行创建、编辑或导出前先确认当前项目，不要仅凭资源名称判断归属。

从用户管理或相关项目入口创建项目、添加成员并分配角色。项目可见性、成员来源和入口可能随角色与部署变化。

## 角色不是全部权限

- **管理员**、**编辑者**、**浏览者**等角色影响可见菜单与操作范围。
- 能查看资源不等于能修改、执行、导出或访问其全部底层数据。
- 角色入口不能被解释为行级、字段级权限，也不能替代工具目录和远程白名单限制。

创建共享资源前确认哪些角色可见。导出和分享时同时检查配置中的凭证、地址、提示词和业务数据。

## 凭证与模型

1. 在受控的凭证管理入口创建对应服务类型的凭证。
2. 在服务商后台生成独立的秘密，只授予所需权限。
3. 将秘密填入本地凭证配置，不写入公开 Markdown、截图或示例仓库。
4. 在目标节点或配置中选择凭证，并用无副作用请求测试。
5. 离职、泄露或用途变化时撤销／轮换秘密，并检查相关引用。

模型配置可在 Agent 对话的模型设置入口完成。凭证与模型可用性受服务商、网络、项目配置和部署条件影响。

## 工具和数据边界

文件、SSH、脚本、HTTP 与 MCP 会触达实际系统。采用最小授权、固定目录和目标白名单，使用参数绑定，禁止将用户输入直接拼接到命令或 SQL。远程通道必须配置用户白名单，不能用隐藏链接代替身份验证。
