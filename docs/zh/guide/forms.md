# 表单与人工协作

表单负责采集输入，表单任务与审批让流程等待人工处理。三者可以组合，但不是同一个节点。

## 设计表单

1. 在**表单**页面选择**新建**，使用设计器添加字段。
2. 配置字段标题、输入方式与必填规则，保存表单。
3. 用测试数据检查字段、校验和提交内容，不要在示例中填写真实敏感信息。

## 三种使用方式

| 方式 | 行为 |
| --- | --- |
| [表单触发器](../trigger_form) | 用户提交表单，启动关联工作流 |
| [表单任务](../form_task) | 流程运行到该节点，为成员创建待填写任务，按条件继续 |
| [审批](../approval) | 流程等待成员审批，按通过、驳回或超时路径继续 |

## 示例：采集 → 处理 → 人工确认

以下示例只使用表单、数据表和工作流，不依赖业务页面发布。

1. 创建一个“申请记录”数据表，包含申请内容和处理状态等字段。
2. 创建“申请提交”表单，收集申请内容。
3. 创建工作流，添加表单触发器并选择该表单，按需配置允许提交的成员。
4. 添加[数据表插入](../data_table_insert)，将申请内容映射到申请记录表，初始状态设为待处理。
5. 如需补充信息，添加表单任务并选择已创建的表单和成员；如需批准，改用审批节点。
6. 在后续分支根据任务或审批结果更新状态，并配置明确的输出。
7. 保存后提交一条测试表单，在执行记录中检查触发数据；有任务时到**用户任务**处理待办。
8. 最后检查数据表记录和流程输出，确认整条路径完成。

表单任务支持按或签／会签等实际配置判断后续流转，具体条件以节点说明为准。不要把提交成功等同于审批通过或流程全部完成。

## 访问与隐私

表单触发器的成员配置决定允许提交的范围；公开提交地址前确认身份验证与访问边界。表单内容会进入执行记录和后续工具，分享截图、日志和链接前检查敏感信息。
