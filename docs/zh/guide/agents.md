# 创建与配置 Agent

## 创建独立 Agent

1. 在 Agent 列表选择**新建 Agent**。
2. 填写名称、描述和系统提示词，明确任务范围、输出格式和禁止执行的操作。
3. 按需设置工作目录。目录是工具可操作的运行现场，不要用不相关的系统目录或敏感资料目录代替。
4. 只勾选任务需要的内置工具、MCP、知识库和工作流。
5. 保存后进入对话，用一个无副作用的小任务验证配置。

## 能力配置的区别

| 能力 | 适用场景 | 配置前提 |
| --- | --- | --- |
| 内置工具 | 文件、搜索等已提供能力 | 检查具体工具权限、目录和外部服务条件 |
| 技能 | 为任务提供方法和操作约定 | 先准备公共或 Agent 专属技能 |
| MCP 工具 | 连接外部工具服务 | 工具已启用，协议与地址配置有效 |
| 知识库 | 检索参考资料 | 文本／向量库及其模型依赖已就绪 |
| 工作流工具 | 把确定的流程作为工具调用 | 流程已启用，并使用同步或异步 API 触发 |

只有符合触发条件并启用的工作流会出现在工作流工具列表。普通手动流程不能直接被当成此类工具；[子流程](../sub_workflow)是另一种流程编排方式。

## 内置 Agent

在主 Agent 卡片的操作菜单中添加内置 Agent，它归属于主卡，在卡片的内置区域管理。它与独立 Agent 的归属、导入导出和删除行为不同；需要改变归属时使用界面提供的升级操作，而不是手动复制配置。

详见[组合子 Agent](sub-agents)。

## 导入与导出

导入、导出用于迁移 Agent 配置。接收外部配置前检查提示词、工具、工作目录和外部地址；不要把配置文件视为可信代码，也不要在公开配置中放入 API Key、Secret 或个人信息。

## 验证与排查

- **工具未出现：** 检查工具是否已创建并启用，以及当前项目和角色。
- **模型无法使用：** 在对话页的模型设置提示中完成配置，Agent 表单中的工具选择不能替代模型配置。
- **执行了非预期操作：** 立即停用相关通道或定时任务，收紧提示词与工具选择，并检查已有执行记录。
